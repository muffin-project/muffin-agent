# ADR-0012 — Il nome: "Muffin" (né MuffinOS né OpenMuffin)

**Contesto.** Il nome è una decisione di scope (BRIEF): "OS" promette il controllo della macchina come portante; "Open" colloca nella famiglia affollata. Criterio dell'owner al checkpoint: "OS se davvero sta un livello sopra Hermes su quel lato". Evidenza (A2): il livello-sopra su macchina non è shippabile-vero oggi (shell/fs/processi = parità con 4/8 peer; UI-automation fragile: OSWorld long-horizon 20,6% binario, zero oltre 163 min); archeologia "OS" negativa (MemGPT→Letta l'ha abbandonato; AIOS accolto con scetticismo; rabbit r1 falsificato); famiglia "Open\*" con 8+ progetti di cui due giganti; i peer credibili usano nomi nudi (Hermes, Goose, Letta, Khoj).

**Decisione.** Il progetto si chiama **Muffin**. Il posizionamento vive nella tagline (modificabile a costo zero), non nel nome. Conseguenza di scope: il system layer entra in v1 come primitivi host-only (M3), non come flagship; "MuffinOS" resta un upgrade *possibile e onesto* quando il livello-sopra sarà reale.

**Alternative scartate.** *MuffinOS ora*: vincola la v1 a mantenere una promessa che l'evidenza dice non mantenibile senza violare "Niente finto" — e il pubblico developer punisce l'overclaim più di ogni altro pubblico (il progetto è un artefatto di credibilità). *OpenMuffin*: leggibilità di categoria pagata con derivatività e confronto diretto imposto coi giganti del prefisso. *Nome nuovo di zecca*: butta la storia e il carattere accumulati; "Muffin" è già distintivo e memorabile.

**Conseguenze.** Più facile: nessuna promessa da difendere nel nome; l'asimmetria gioca a favore (aggiungere "OS" dopo = upgrade credibile; toglierlo dopo = ritirata pubblica). Più difficile: la categoria va spiegata nella tagline/README ("personal agent runtime" o simile — scelta di copy, non di architettura).

**Verifica namespace (2026-08-04, eseguita — era dichiarata NON VERIFICATA).** npm: `muffin` **occupato**; `muffin-os`, `muffinos`, `openmuffin`, `muffin-agent` liberi. GitHub: gli handle/org `muffin`, `muffinos`, `muffin-os` sono **occupati**, `openmuffin` libero. Repo omonimi rilevanti: `klen/muffin` (691★, web framework Python), `thephpleague/factory-muffin` (537★), **`linuxmint/muffin` (244★, il window manager di Cinnamon)**.

Conseguenze operative, che non cambiano il nome ma vincolano il packaging:
- **Il progetto resta "Muffin"** (è il nome della persona, ed è suo); il repo vive sull'account personale (`<owner>/muffin`), non serve un'org.
- **Pacchetto npm scoped** (`@muffin-ai/*` o simile): `muffin` non è disponibile e uno scope evita anche il rischio di squatting sui nomi liberi.
- **Attenzione al binario**: su Linux Mint esiste già `/usr/bin/muffin` (il window manager). Un binario globale `muffin` installato via npm finirebbe prima nel PATH e **ombreggerebbe il window manager dell'utente**. Mitigazione: l'installer rileva un `muffin` già presente nel PATH e propone un nome alternativo o un alias, invece di sovrascrivere in silenzio. Questo è anche un argomento a favore del nome nudo su un ipotetico "MuffinOS": un progetto che si chiama OS e rompe il window manager di una distro sarebbe una brutta prima impressione.

**Reversibilità.** Il rename in avanti (Muffin→MuffinOS) è a costo basso e narrativamente positivo; il segnale che lo sblocca è definito in 07/04 §5: computer-use long-horizon sopra soglia utile o API OS deterministiche che rendano il controllo della macchina affidabile — allora il nome può seguire il fatto. Da fare prima dell'annuncio: verifica collisioni namespace (npm/GitHub) per "muffin" [NON VERIFICATO in Fase A].

## §revisione 2026-08-09 — lo slug tecnico è `muffin-agent`

Decisione owner: repo + package = **`muffin-agent`** (era il provvisorio `muffin-next`, tampone per la collisione macOS case-insensitive col checkout `muffin` esistente); **nome-prodotto, comando (`muffin`) e identità restano `muffin`** — cioè esattamente lo split che l'ADR implica (l'identità nel nome, la categoria/technicalità altrove). `muffin-agent` era già **verificato libero su npm** dal check di questa ADR (2026-08-04, sopra). Caveat registrato e accettato: `-agent` foregrounda una gamba sola (agente) mentre il progetto è agente+specchio (ADR-156) — ma è uno slug di repo, non una promessa: l'identità la porta il nome-prodotto "Muffin". Al cutover il repo può riprendersi `muffin` se il vecchio si spegne. Eseguito in `~/dev/muffin-agent` (`4b6a72e`): directory, `package.json name`, e l'hook `guard-frozen-deps` del vecchio worktree aggiornati insieme; nulla nel codice hardcodava il vecchio nome; 347 test verdi dal nuovo path.

## §revisione 2026-08-09 (2) — l'installer collision-safe è codice, non più solo dichiarazione

Il comando esiste davvero: `bin: { muffin: dist/cli/main.js }`, lo script `compile` emette in `dist/` e **bundla gli asset non-TS** che `init`/`profiles` leggono a runtime (`defaults/`, `agent/profiles/*.json`) — senza, il bin compilato girerebbe solo via `tsx`. Provato end-to-end: `muffin --version` dal bin compilato, e `muffin init` in una home temporanea (`MUFFIN_HOME`) che crea RoT+config+db pescando gli asset da `dist/`. Un baco latente che l'emit introduceva — `main.ts` leggeva `../package.json`, corretto da `cli/` ma rotto da `dist/cli/` — è chiuso risalendo la gerarchia finché trova il file.

La mitigazione che questa ADR aveva solo **dichiarato** (rilevare un `muffin` già nel PATH e proporre un alias invece di sovrascrivere) ora vive in `install.sh`, con una precisazione che conta: la detection è **per identità, non per nome né per stringa di versione**. Il window manager di Cinnamon si chiama anch'esso `muffin` e stampa anch'esso una `--version`, quindi l'unico test affidabile è *"il `muffin` sul PATH risolve a **questa** build?"* (via `realpathSync`). Se è estraneo → il comando si installa come **`muffin-agent`**, mai ombreggiando il WM, mai `sudo`, mai in una dir di sistema: symlink in `~/.local/bin`. Override esplicito `MUFFIN_CMD=muffin`. Su macOS non c'è collisione (il link finisce in `/opt/homebrew/bin`), quindi il default resta `muffin`.

Perché non basta `npm i -g`: il campo `bin` è **statico** (`muffin`), non sa adattarsi alla collisione — la sicurezza-nome vive nell'installer, non in `package.json`. Il modello `curl … | bash` remoto resta per dopo: il repo è privato, quindi oggi l'installer è locale (da un clone). Codice: `muffin-agent@918cb44` (`install.sh`, `tsconfig.build.json`, `package.json` bin/compile/prepare, `cli/main.ts` readOwnVersion, `LICENSE`).
